# Личная блокировка пользователей

**Статус:** функция ещё не реализована. UB-01 утверждена 29 октября 2026;
UB-03 подготовила fixtures и карту проверок. Замеров производительности пока нет.
[План и текущий шаг](superpowers/plans/2026-10-29-user-blocking-task-breakdown.md).

Одного решения A → B достаточно для ограничения A ↔ B. Каждый снимает
только свой блок; доступ возвращается после снятия обоих. Личный блок
не меняет глобальный статус аккаунта и административные санкции.

## Утверждённые правила

29 октября 2026 пользователь подтвердил: «Утверждаю весь пакет UB-01».
Пакет включает D01–D08, английский интерфейс L01 и строки C01 ниже.

| ID | Правило |
| --- | --- |
| D01 | Исторические голоса и лайки сохраняются; блок не меняет глобальные результаты и счётчики реакций. Отзыв реакции на недоступный объект возвращает общий `404 not_found` до восстановления доступа; после него действуют обычные сроки и правила. Удаление своего комментария по ID сохраняет `204 No Content` даже в скрытом опросе. |
| D02 | В доступном опросе скрытый корень заменяется «Комментарий недоступен», только если у него есть доступные ответы A/C. Ответы остаются достижимыми, включая следующие страницы. Заглушка не содержит автора, body, excerpt, аватар или реакции; ответить скрытому корню нельзя. Опрос B целиком остаётся недоступен A. |
| D03 | Старые уведомления, ставшие недоступными из-за блока, окончательно исключаются из inbox обеих сторон, unread и адресного чтения; их push не отправляется повторно. Unblock не возвращает историю, даже если произошёл до запуска worker. Новые разрешённые события после снятия всех блоков работают обычно. |
| D04 | Первый пользовательский релиз включает Flutter для Android и iOS и публичный React web: полный цикл block/list/unblock, все точки входа, синхронизацию и доступность. Flutter web/desktop не входит. |
| D05 | Защита относится к идентифицированным аккаунтам. Публичный guest-доступ, другой аккаунт, сохранённые файлы/снимки и публичные URL аватаров остаются за её границей. Профили, опросы и изображения опросов авторизованного viewer проверяются сервером; кэш guest→login не обходит политику. |
| D06 | Обе существующие подписки снимаются атомарно со счётчиками. После unblock не восстанавливаются; новый follow возможен вручную после снятия всех блоков и при обычном разрешении доступа. |
| D07 | Moderator и superadmin можно лично блокировать как обычных участников. Их пользовательские профили и контент подчиняются той же политике; служебные endpoints, полномочия и системные сообщения сохраняются. Блок не меняет глобальные санкции, роли и чужие сессии. |
| D08 | Блок бессрочен до снятия/удаления аккаунта. Нет временных блоков, продуктовой квоты на число блоков и бессрочного журнала причин; причина не запрашивается. Частоту запросов ограничивает rate limit. Сохраняются границы первого релиза: без mute, IP/device-блока, выявления новых аккаунтов, массовых операций/импорта/экспорта, платных ограничений, нового чата/упоминаний и персонального пересчёта итогов. |

Другой стороне не отправляется уведомление о block/unblock. Ответы не раскрывают
встречный блок. Жалоба — отдельное действие. Блок привязан к UUID; повторно занятый
username не наследует отношения. Удаление любого участника удаляет связи.

## Пользовательский сценарий

Действие есть в профиле, меню опроса и комментария и относится к их автору.
После подтверждения и успеха скрытые данные удаляются со всех экранов и из кэша.
В настройках — приватный список с догрузкой и снятием своего решения, в том числе
для недоступной цели.

При timeout клиент сверяет состояние, не объявляет успех и не возвращает скрытые
данные до ответа. Unblock подтверждает только снятие своего решения. Фокус, pending
и ошибки доступны через ARIA/Flutter semantics.

Поставки: Android и iOS через Flutter, публичный React web. Язык первого релиза —
английский; новая русская локализация не входит. Android-only выпуск меняет объём.
Для iOS нужны отдельная сборка, VoiceOver, push, reconnect и resume.

## Контракт для детализации в UB-02

Это предложение следующей задачи, не существующие endpoints.

| Метод и путь | Назначение |
| --- | --- |
| `PUT /users/:userId/block` | Установить свой блок |
| `DELETE /users/:userId/block` | Снять свой блок |
| `GET /users/:userId/block` | Сверить исходящее решение |
| `GET /profiles/me/blocks?limit=20&cursor=…` | Приватный список, limit 1–50 |
| `GET /profiles/me/visibility` | Сверить ревизию видимости |

Мутация/сверка возвращает `{ targetUserId, blockedByViewer, viewerVisibilityRevision }`.
Ревизия — десятичная строка. Список: `items`, обязательный nullable `nextCursor`,
ревизия; элемент: `userId`, `blockedAt`, `targetAvailable` и `user` с публичными
полями. Для недоступной цели `user: null`. Нет полей о встречном блоке, email
и причинах недоступности.

Все маршруты требуют авторизацию. Self — `400 invalid_block`, неверный ввод —
`400 validation_error`. PUT неизвестной/удалённой цели — общий `404 not_found`.
GET валидного UUID без своего блока возвращает `false`, не раскрывая существование
цели. DELETE идемпотентен даже при отсутствии цели. PUT существующей цели под
административным баном допустим. Дата повторного блока не меняется.

Ограниченные профиль, опрос и взаимодействия возвращают общий `404 not_found`;
удаление своего комментария сохраняет `204`. Персонализированные ответы —
`no-store`, курсор привязан к владельцу, cookie-мутации сохраняют проверку origin.
Rate limits, совместимость DTO и минимальные версии определяются в UB-02.

## Требования к реализации

- Блок, снятие обеих подписок и четырёх счётчиков, ревизии, подавление истории
  уведомлений и outbox фиксируются одной транзакцией. Повтор не меняет счётчики.
- Проверка внутри мутации сериализована с block/unblock. Пользовательские locks
  берутся в едином порядке до locks опроса, комментария и push jobs.
  Ошибка проверки доступа запрещает действие.
- Фильтрация выполняется до limit; повторно проверяются hydration, старые cursor/snapshot,
  поиск, профили и скрытые корни. Короткая страница не теряет доступный хвост.
- Заглушка корня — `{ kind: 'unavailable', rootId, availableRepliesCount }`;
  обычный элемент — `{ kind: 'comment', comment }`. В заглушке нет автора, body,
  preview, avatar и реакций. Старый клиент не получает скрытый body ради совместимости.
- Уведомления проверяют actor и владельца целевого контента. Подавленная история
  не возвращается после unblock, даже если он был до запуска worker.
  Правило действует для inbox, unread и адресного read.
- Push проверяется перед разрешением отправки, включая claimed jobs и retry.
  Уже разрешённую до commit отправку отозвать невозможно. Рубеж авторизации
  и suppression фиксируются в UB-02.
- Каждая realtime-доставка проверяется по получателю, включая полный payload опроса.
  `user_blocks.changed` виден только владельцу; `viewer.visibility_invalidated`
  содержит ревизию без идентификатора другой стороны.
- Данные и ревизия чтения согласованы: старые данные нельзя маркировать новой ревизией.
  Session epoch защищает от позднего HTTP/socket ответа после logout, смены аккаунта
  и Back; ревизии — после block/unblock.
- После reconnect/resume и потери Redis события восстанавливаются через outbox
  и HTTP. Офлайн-клиент не обещает немедленного стирания уже загруженных данных.
- Media и conditional GET проверяются до `304`; общий кэш и guest→login не обходят
  политику. Публичные ссылки аватаров остаются вне её границы.
- Служебная модерация, жалобы и удаление аккаунтов сохраняются. Личный блок
  moderator/superadmin действует на обычный пользовательский контент.
- Rollback отключает создание и UI, но сохраняет enforcement, список и unblock.
  Сервер без проверок нельзя возвращать к защищённым данным.

## Тексты интерфейса C01

Точные утверждённые строки. `{account}` — доступное текущее имя; при его отсутствии
используется нейтральный заголовок. UUID не показывается как имя.

| Контекст | Текст |
| --- | --- |
| Действие в меню | Block user |
| Действие на нейтральном экране по известному ID | Block account |
| Заголовок block | Block {account}? / Block user? |
| Подтверждение block | You will no longer see each other's profiles or posts or be able to interact. You will unfollow each other, and follows will not be restored automatically. Existing votes and likes will remain. The user will not be notified about the block. |
| Кнопки block | Cancel / Block |
| Успех block после ответа сервера | User blocked |
| Заголовок списка | Blocked users |
| Пустой список | You haven't blocked anyone yet. |
| Недоступная цель в списке | Account unavailable |
| Действие и кнопка unblock | Unblock |
| Заголовок unblock | Unblock {account}? / Unblock user? |
| Подтверждение unblock | You will be able to see each other's available content and interact again if no other restrictions apply. Follows will not be restored automatically. |
| Кнопки unblock | Cancel / Unblock |
| Успех unblock после ответа сервера | Your block has been removed. |
| Недоступный профиль | Profile unavailable |
| Недоступный опрос | Post unavailable |
| Заглушка комментария | Comment unavailable |
| Пояснение к счётчику обсуждения | Some comments may be unavailable. |
| Загрузка / отправка | Loading… / Saving… |
| Ошибка списка / догрузки | Could not load blocked users. / Could not load the next page. |
| Нет сети | You're offline. Check your connection and try again. |
| Повтор | Retry |
| Подтверждённая ошибка изменения | Could not save the change. Try again. |
| Неизвестный результат timeout, до сверки | Could not confirm the change. Checking your block status. |
| Сверка после timeout недоступна | Could not check your block status. Try again. |
| Справка о границе защиты | Blocking limits interaction between these accounts. Public content may still be accessible while logged out or from another account. Public avatar links, saved files and screenshots are not revoked. |

## Приёмка

Проверяется на API, Android, iOS и web в пределах соответствующего сценария.

| ID | Проверка | Ожидаемый результат |
| --- | --- | --- |
| AC-01 | A блокирует B из профиля, опроса и комментария | Подтверждение, успешное сохранение, немедленная очистка; действие относится к автору выбранного объекта |
| AC-02 | Гость, self, чужой block-list, некорректный UUID | Предсказуемые ошибки; нет возможности менять чужие отношения |
| AC-03 | Повтор PUT/DELETE, timeout и повтор запроса | Конечное состояние достоверно; дата существующего блока и счётчики не портятся |
| AC-04 | A→B при подписках в обе стороны | Обе подписки сняты, все затронутые счётчики верны, после unblock подписки не восстановлены |
| AC-05 | Главная, подписки, Explore, поиск, popular users, списки C | A и B не встречают друг друга и чужие опросы; для C обычное поведение |
| AC-06 | Прямой профиль, опрос, изображение опроса, комментарий, ответы | Нет утечки body/автора/quoted preview; правила заглушки и чтения ответов соблюдены |
| AC-07 | Follow, голос/смена, лайк, комментарий, ответ по известным ID | Новое взаимодействие между A и B невозможно в обоих направлениях |
| AC-08 | Общий опрос C, скрытый корень B с ответами A/C | Ответы A/C доступны, B скрыт; ответ B запрещён; независимый комментарий A к опросу C разрешён |
| AC-09 | Исторические голоса, лайки, комментарии и агрегаты | Сохраняются; блок не меняет результаты; глобальная статистика не становится viewer-specific |
| AC-10 | Старые notification, unread, адресный notification, queued/retried push | Недопустимые события скрыты/подавлены, нет доставки после разрешённой границы; после unblock нет старого backlog |
| AC-11 | WebSocket с целым poll, позднее событие и две API-реплики | Скрытый объект не приходит, события C без скрытой личности допустимы, нет общего события о личном блоке |
| AC-12 | Две вкладки, два устройства, resume/reconnect, потеря invalidation | Сходимость по ревизии; старые ответы не возвращают скрытые данные; офлайн-граница явно учтена |
| AC-13 | Старый snapshot/cursor, разреженная выдача, блок между страницами | Нет скрытого контента, зацикливания и дубликатов; доступный хвост достижим |
| AC-14 | Встречный блок, одновременные block/unblock | Каждая сторона меняет только своё решение; ограничения действуют до снятия последнего блока |
| AC-15 | Гонка block с follow/vote/like/comment/push | Результат соответствует порядку commit/авторизации отправки; отсутствует проверка только до транзакции |
| AC-16 | Жалоба после блока и просмотр дела модератором | Жалоба обрабатывается независимо, доказательства доступны только служебному контуру, санкции продолжают работать |
| AC-17 | Блок роли moderator/superadmin | Личные взаимодействия ограничены; служебные действия и системные сообщения не нарушены |
| AC-18 | Удаление A/B, административный бан и его отмена, смена username | Нет утечки удалённых данных и оставшихся связей; личный и административный статусы независимы |
| AC-19 | Общий HTTP-кэш, guest→login, cookie/Bearer, Back, смена аккаунта | Общая/предыдущая копия не обходит viewer-проверку; чужое состояние не переносится между аккаунтами |
| AC-20 | Снятие последнего блока | Доступный контент возвращается после обновления; подписки и старые уведомления не восстанавливаются |
| AC-21 | Пагинируемый block-list: пусто, ошибки, недоступный target, retry | Список приватен, управляем, стабилен; недоступная цель не мешает снять своё решение |
| AC-22 | Удаление собственного комментария в скрытом опросе | Удаление работает по прежним правилам владения без возврата скрытого содержимого |
| AC-23 | Недоступность PostgreSQL/Redis, рестарт API/worker, повтор outbox | Нет разрешения доступа при ошибке проверки, committed-блок сохраняется, синхронизация восстанавливается |
| AC-24 | Клавиатура, screen reader, Flutter semantics и фокус после скрытия | Подтверждение и управление доступны без мыши; фокус не теряется |

Нужны проверки A/B/C, всех четырёх состояний блока, cookie/Bearer/guest, старых
клиентов, двух API-реплик, сбоев PostgreSQL/Redis, конкурентных мутаций и повторной
доставки. Карта путей — [endpoint-matrix.md](user-blocking-evidence/endpoint-matrix.md).

До измерений ориентиры: p95 block/unblock ≤ 1 с без пользовательской сети,
обновление активного клиента ≤ 2 с; регрессия feed/search/comments не более 20%
при одинаковой нагрузке. Списки для проверки: 0/100/1 000/10 000 блоков и большой
входящий список. Это тестовые размеры, не квоты и не измеренные SLO.
Защита не ослабляется ради задержки или совместимости.

Метрики: ошибки, latency, конфликты locks, outbox lag/retry, suppression,
сверка ревизий и отбрасывание устаревших ответов. В labels и продуктовую аналитику
не включаются UUID пар, имена, тексты и причины. До выпуска нужны результаты всей
матрицы, нагрузка, совместимые миграции, rollback и решение владельца выпуска.

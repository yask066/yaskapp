# Database Schema

The initial PostgreSQL schema lives in:

```text
services/api/src/db/migrations/001_initial_social_schema.sql
```

## Tables

- `users`: authentication identity and account status.
- `profiles`: public profile data and denormalized counters.
- `polls`: poll metadata, visibility, counters, and optional media key.
- `poll_options`: ordered answer options for each poll.
- `poll_votes`: user votes with one vote per poll in the current MVP.
- `comments`: poll comments and nested replies.
- `likes`: likes for either polls or comments.
- `follows`: follower/followee graph.
- `notifications`: user notification inbox.
- `notification_preferences`: per-user in-app and push notification settings.

## Notes

- Primary keys use UUIDs generated by PostgreSQL.
- Object storage references are stored as object keys, not public URLs.
- Vote, like, and follow uniqueness is enforced at the database level.
- Counters are denormalized fields intended to be updated transactionally by the API.
- Notifications use an optional unique `deduplication_key` to make repeated domain
  events safe, and retain nullable poll/comment references when targets are deleted.

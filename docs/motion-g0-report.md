## Контракт свежести и scope review

В checkout `c786843` реализация ревизий уже присутствует в API и shared-модели: Poll DTO включают независимые `votes`/`likes`/`comments` revisions; repository hydration использует `REPEATABLE READ READ ONLY`; Search строит viewer fields и revisions из одного query; realtime удаляет viewer-specific поля. Web и Flutter имеют соответствующие revision-aware reducers/stores. Это подтверждает статический охват текущих источников, но не закрывает обязательную M04 проверку на отдельной БД и не доказывает все rollback/no-op/older-client условия одним актуальным integration run.

Документы отстают от кода: [M03 contract](motion-poll-state-contract.md) помечает M04 как неисполненную, [M03 verification](motion-scroll-loading-evidence/m03-verification.txt) говорит, что backend revisions не проверены, а M04 в implementation plan остаётся с незакрытыми пунктами. До повторного G0 решения нужно актуализировать эти записи с воспроизводимыми результатами M04, а не считать code presence подтверждением выполнения.

По M17 evidence новых entry/count/bar/like/shimmer effects не включали. В [audit](motion-scroll-loading-audit.md#1-матрица-экранов-и-текущая-реализация) отдельно описаны существующие Flutter TweenAnimationBuilder transitions; они относятся к прежнему поведению, а не к задачам M19–M25. Новые motion-задачи M19–M25 не допущены.

## Открытые условия для повторного gate review

1. Завершить и задокументировать M04 API/DB integration evidence по атомарным revisions, no-op/rollback, viewer isolation, старому клиенту и публикации только после commit; синхронизировать M03/M04 документы с фактическим кодом.
2. Закрыть отсутствующие статические geometry/anchor сценарии Flutter, включая измерение допустимого сдвига и границ счётчиков; сохранить команды, сборки и результаты.
3. Получить поддержанную классификацию Flutter app frames для AC-12 и повторяемый iOS baseline по матрице PRD. Если устройство или измеритель недоступны, записать это как блокер, а не pass.
4. Зафиксировать идентификаторы tested builds для обеих платформ и назначить ответственного Engineering/QA, который пересмотрит evidence и подпишет итоговое решение.

До закрытия всех пунктов **G0 остаётся NOT PASSED для обеих платформ**. M19–M25 не разблокированы; допустимы работы по стабилизации и сбору недостающих evidence.
